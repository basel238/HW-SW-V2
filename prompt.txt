===============================================================================
 KEY DESIGN DECISION: PHASE SEPARATION (from prompt 2)
===============================================================================

The request "make sure the scripts don't add overhead" required restructuring,
not a flag. Profilers perturb what they measure: perf record with DWARF
unwinding adds ~10-30 % wall time, cProfile adds 2-5x. The resolution was to run
each measurement in its own process and never quote timing from an instrumented
run:

  phase 2  clean timing   NO profiler        <- the only quotable numbers
  phase 3  perf stat      counting mode ~1 % IPC / cache / branches
  phase 4  perf record    sampling, high ovh flame graphs; timing DISCARDED
  phase 5  cProfile       tracing, 2-5x      call COUNTS only
  phase 6  pyperformance  own harness        citable mean +- stdev

Phases 4-5 write their wall time to files named *_DO_NOT_QUOTE_timing.txt so it
cannot be mistaken for a result. Reported statistic is the MEDIAN of N
independent processes, with the run-to-run noise printed alongside; compare.sh
refuses to endorse an improvement smaller than 2x the measured noise.

===============================================================================
 AI ERRORS FOUND AND CORRECTED
===============================================================================

These were caught by running the code, not by reading it.

 1. WRONG PHYSICS TOLERANCE (nbody verify)
    The AI asserted absolute energy drift < 1e-6 over 1000 steps. That is
    physically wrong: a symplectic integrator has BOUNDED, OSCILLATORY energy
    error, not zero. The gate failed immediately (actual drift ~1.7e-4).
    Fix: relative tolerance < 1e-3, plus a separate 1e-9 relative cross-check
    against the baseline implementation for the reassociation-only difference.

 2. NON-BIT-EXACT "SAFE" FP OPTIMIZATION (raytrace)
    The AI replaced three divisions with one reciprocal + three multiplies and
    asserted this was bit-exact. It is not: (1/m)*x rounds twice, x/m once,
    giving ~1 ULP. Because the renderer contains DISCONTINUITIES (shadow
    hit/miss tests), that 1 ULP flipped an occlusion test at one shadow-edge
    pixel, changing it by 118/255.
    Fix: exact division is now the default; FAST_FP=1 opts in and deliberately
    fails the gate, which is kept as a demonstration.
    This became a substantive finding for the report: "safe" FP strength
    reduction is only safe in branch-free numeric code.

 3. BASH ARRAY EXPANSION UNDER set -u  (would have broken the real VM)
    "${EMPTY[@]}" raises "unbound variable" under set -u in bash 3.2. The
    affected arrays (PIN when taskset is absent, ev when no perf events are
    supported) are empty in exactly the NORMAL no-PMU QEMU case the code was
    written to handle. The pipeline aborted at phase 0.
    Fix: guarded all 19 expansions as ${ARR[@]+"${ARR[@]}"}, and rewrote
    filter_supported_events to build a string rather than an array.

 4. NESTED HEREDOC MIS-PARSE (gen_report.sh)
    A heredoc inside $(...) inside another heredoc made bash mis-associate the
    inner delimiter, silently disabling variable expansion for the rest of the
    outer heredoc -- ${BENCH} appeared literally in the generated report.
    Fix: precompute the per-benchmark text into a variable before the heredoc.

 5. set -e VS grep -c
    `grep -c '[TODO' | xargs ...` exits non-zero when the count is 0, aborting
    the script under set -e -- i.e. it failed precisely when the report was
    complete. Fix: capture with `|| true`.

 6. FALSE DEPENDENCY CLAIM
    doctor.sh demanded bash >= 4 "for associative arrays". No associative array
    is used anywhere. Fix: requirement corrected to 3.2.

 7. INVALID CPU PINNING
    PIN_CPU=1 was used unconditionally; on a 1-vCPU guest every taskset call
    would fail, silently killing all measurements. Fix: build_pin() clamps
    PIN_CPU to an existing CPU and warns.
